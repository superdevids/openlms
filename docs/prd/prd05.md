## 1. Ringkasan Eksekutif (BLUF)

**PRD development ini menetapkan program penutupan seluruh gap hasil audit read-only 2026-08-07 (67 item, ID G-01–G-67, disebut "register 61-gap" pada rujukan audit) agar openlms siap menangani target kapasitas 500 pengguna idle dan 1.500–2.000 pengguna ujian bersamaan (puncak), tanpa 429, tanpa timeout, dan tanpa temuan CRITICAL/HIGH yang tersisa.**

- **Akar masalah utama bukan fitur baru, melainkan kontrak web↔API yang belum sinkron.** Lima temuan CRITICAL (G-01..G-05) membuat alur ujian dan kuis sebagai inti produk tidak berfungsi end-to-end: autosave ditolak 400 (batch vs single answer), daftar ujian 404 (`/exams` vs `/exam`), alur kuis rusak, cookie sesi `openlms_session` tidak pernah dibuat, dan tidak ada scheduler auto-submit server-side. Kelima item ini adalah prioritas 1 (Cluster A) yang harus tuntas di Sprint 1 sebelum pekerjaan performa/feature apa pun.
- **Performa bukan pilihan: target kapasitas naik dari baseline 500 siswa/shift (prd04 §13 Q7) menjadi 1.500–2.000 pengguna puncak.** Cluster B (G-06..G-17) menghilangkan blokir skala: rate limit per-IP yang memblokir NAT sekolah, guard 4–6 query per request tanpa cache, autosave 4 query serial, race JSON kuis, auto-submit full-scan tanpa indeks, pertumbuhan append-only `ExamAnswerLog`, fan-out notifikasi tanpa Redis adapter, N+1 rollover/attendance/payroll, list invoice unbounded, pool koneksi tidak dikonfigurasi, dan timer ujian yang bergantung client.
- **Keamanan dan integritas data dikerjakan paralel di Sprint 2 (Cluster D + F):** IDOR keuangan (G-24), CSRF (G-21), idempotency pembayaran (G-35), race `invoice_no` (G-36), dan rollback PPDB (G-39) adalah temuan integritas data/uang yang tidak boleh lolos ke produksi.
- **Fitur bisnis SMA/SMK (Cluster H), observability (Cluster E), testing (Cluster J), dan ops/infra (Cluster K) dijadwalkan di Sprint 3** sesuai instruksi roadmap; catatan risiko: komponen observability minimal dan testing modul kritis ditarik lebih awal pada done-definition tiap item Sprint 1–2 agar ujian sungguhan tidak berjalan "buta".
- **Definisi selesai (DoD) terukur:** ≥1.500 pengguna ujian bersamaan tanpa 429/timeout, p95 autosave < 300 ms, seluruh unit+integration+E2E test PASS, coverage ≥ 80% (web+api), 0 temuan CRITICAL/HIGH terbuka, dan load test k6 ≥ 1.500 VU lulus (§15).

Register ini memuat 67 baris (ID G-01–G-67) — penamaan "61 gap" pada rujukan audit dipertahankan untuk konsistensi lintas dokumen; seluruh baris terdokumentasi di §2 dengan severity, cluster, evidence, dan status.
