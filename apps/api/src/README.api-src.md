# README.api-src.md — Struktur Aplikasi API (apps/api)

## Fungsi Folder

`apps/api/src/` berisi aplikasi backend **NestJS 11** untuk opensis. Backend ini
menyediakan REST API (prefix global `/api/v1`), real-time via Socket.IO (namespace
`/ws`), otorisasi RBAC fail-closed, serta antrean job opsional (BullMQ/in-process).
Saat ini ada **37 modul NestJS + 1 folder konstanta** (`database/`) di
`src/modules/` (total 38 entri).

## Struktur Folder

| Path                | Isi                                                                                                                                 |
| ------------------- | ----------------------------------------------------------------------------------------------------------------------------------- |
| `src/main.ts`       | Bootstrap NestJS (helmet, CORS dari `CORS_ORIGINS`, trust proxy, pino, body limit 50kb, fail-fast CORS/COOKIE_SECURE di production) |
| `src/app.module.ts` | Module agregator: semua modul domain + middleware global (RequestId, RateLimit)                                                     |
| `src/common/`       | Infrastruktur lintas-modul: guard, decorator, filter, middleware, cache util (lihat `common/README.common.md`)                      |
| `src/modules/`      | Modul domain — satu folder per fitur (lihat tabel di bawah)                                                                         |

## Konvensi

- **RBAC fail-closed:** `AuthGuard` (global) → `PermissionsGuard` (`@RequirePermission`) →
  `FeatureFlagGuard` (`@Feature`). Aktor selalu dibaca dari `request.requestContext`
  (`@CurrentUser`/`AuthUser`), **bukan** dari header klien (JWT canonical).
- **Lapisan per modul:** `Controller` (route + deklarasi permission) →
  `Service` (logic domain + scope) → akses data via Prisma (`@opensis/database`).
  Sebagian modul memakai lapisan `Store` ekstra (mis. `finance/finance.store.ts` +
  `prisma-finance.store.ts`, `lms/lms-audit.ts` untuk penulisan AuditLog).
- **RBAC scope (sekolah vs self):** permission `*:school` = akses semua data;
  `*:self` = hanya data sendiri/anak. Contoh: `invoice:read:self` membatasi
  SISWA/WALI_MURID ke tagihan milik sendiri/anak (SEC-002); `user:write:self` di
  parent-portal membatasi ke wali milik aktor (SEC-001).
- **Cookie JWT & fail-fast:** cookie `httpOnly + Secure + SameSite=Lax`; di
  `NODE_ENV=production`, boot akan **gagal (throw)** bila `COOKIE_SECURE !== "true"`
  atau `CORS_ORIGINS` kosong (lihat `src/main.ts`).
- **Kontrak endpoint per modul:** lihat `README.<modul>.md` di tiap folder.
